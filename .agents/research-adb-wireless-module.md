# ADB and wireless projection: module research

Paths and line numbers below are relative to `tmp/`. Source review only; no head-unit test was performed.

## Verified facts

**The conflict and the fix.** HMG-API has three distinct mods: `adb` controls USB and TCP ADB, `adbd` optionally replaces the insecure daemon, and `wireless-carplay-aa` enables wireless projection. The `adb` mod is the coexistence fix, not a special part of the wireless mod (`HMG-API/mods/adb/mod.json:2`, `HMG-API/mods/adbd/mod.json:2`, `HMG-API/mods/wireless-carplay-aa/mod.json:2`). The stock Engineering Mode / NEMESIS “Enable ADB” switch sets `persist.service.adb.tcp.enable=1`; the `set_adb_ip` init service then assigns `eth0` `192.168.0.123`. The car hotspot is `wlan0` `192.168.0.1/24`; DHCP replies can leave via `eth0`, so a phone joins Wi-Fi without receiving an address and wireless projection fails (`HMG-API/CLAUDE.md:56`, `HMG-API/core/runtime/java/hmgapi/engine/Engine.java:1900`). `adb` forces that switch to `0` and, when its TCP setting is on, sets `persist.adb.tcp.port=5555` and restarts `adbd`, preserving TCP ADB without assigning `eth0` an address (`HMG-API/mods/adb/patches.json:3`, `HMG-API/mods/adb/patches.json:6`). A restart is needed to clear an `eth0` address already assigned by the old switch (`HMG-API/core/runtime/java/hmgapi/engine/Engine.java:1914`). The engine warns when the old switch is on alongside a wireless-feature mod without `adb` (`HMG-API/core/runtime/java/hmgapi/engine/Engine.java:1908`).

**What changes.** `adb` has independently selectable USB and TCP parts. USB on sets `persist.sys.usb.config=adb` and mirrors it to live `sys.usb.config`; USB off uses `host,adb`. TCP off unsets `persist.adb.tcp.port`; each TCP change restarts `adbd` (`HMG-API/mods/adb/mod.json:10`, `HMG-API/mods/adb/patches.json:3`). Defaults are USB on, TCP off. USB device mode prevents that port from accepting a phone or USB drive (`HMG-API/mods/adb/settings.json:4`). The intended connection is from a computer on the car hotspot: `adb connect 192.168.0.1:5555` (`HMG-API/mods/adb/settings.json:7`). This is not a declared `wlan0`-only bind: the bundled AOSP replacement daemon uses `socket_inaddr_any_server`, accepting on all IPv4 interfaces; the stock daemon's exact bind was not verified here (`HMG-API/third_party/aosp-4.4.4/adb/transport_local.c:165`; `HMG-API/third_party/aosp-4.4.4/adb/adb.c:1349`). These mods declare no ADB-specific firewall rule or route. The `adbd` mod instead bind-mounts a rebuilt Android 4.4 daemon over `/sbin/adbd` and restarts the service; the read-only root file is untouched and disabling/restarting restores the stock daemon (`HMG-API/mods/adbd/patches.json:3`, `HMG-API/mods/adbd/mod.json:8`, `HMG-API/core/runtime/java/hmgapi/engine/Engine.java:39`). HMG-API reports that the stock daemon does not check ADB keys, so anyone able to reach ADB on the hotspot can connect; the replacement daemon adds Android's authorization prompt for USB and Wi-Fi (`HMG-API/CLAUDE.md:50`, `HMG-API/mods/adbd/mod.json:8`).

`wireless-carplay-aa` declares wireless feature flags, comments out the hotspot feature XML entry, sets projection/bridge properties, adds an audio library, and uses Java/native hooks for projection behavior (`HMG-API/mods/wireless-carplay-aa/mod.json:36`, `HMG-API/mods/wireless-carplay-aa/mod.json:53`, `HMG-API/mods/wireless-carplay-aa/mod.json:68`, `HMG-API/mods/wireless-carplay-aa/patches.json:11`). Its present `mod.json` has **no `network` declaration** (`HMG-API/mods/wireless-carplay-aa/mod.json:1`). A separate whitelist-firewall issue exists on some cars: the Ioniq 6 example permits CarPlay ports on wired `ncm0` but not hotspot `wlan0` (`HMG-API/CLAUDE.md:62`). HMG-API's *schema* supports hotspot accept rules through `network`, applied by root service `hmgapi net` from `state/net.sh`, checked every 10 seconds and removed on disable; that example is not evidence that the current wireless mod ships those rules (`HMG-API/docs/mod-reference.md:221`, `HMG-API/docs/mod-reference.md:236`). ADB TCP alone has no declared firewall exception; reachability on a particular car remains to be tested.

**Restore.** HMG-API records original property values, applies live mirrors/service restarts only when values change, and puts recorded values back when a mod no longer owns them (`HMG-API/core/runtime/java/hmgapi/engine/Engine.java:1691`, `HMG-API/core/runtime/java/hmgapi/engine/Engine.java:1720`). Its ADB host test restores the initial `persist.service.adb.tcp.enable`, USB config, and TCP port (`HMG-API/mods/adb/test.sh:43`). File changes are rebuilt from stock backups as one transaction; bind mounts clear on restart (`HMG-API/core/runtime/java/hmgapi/engine/Engine.java:20`, `HMG-API/core/runtime/java/hmgapi/engine/Engine.java:39`). Removing a mod deletes its folder but requires a subsequent `engine apply` to restore its changes (`HMG-API/core/runtime/java/hmgapi/engine/Packages.java:194`).

**Leafia and NEMESIS.** Leafia's wireless package checks the old switch at install, records what it changed, sets `persist.adb.tcp.port=5555` only if empty, then turns the old switch off; uninstall reverses only the recorded changes (`HMG-Leafia-Plus/packages/wireless-carplay-aa/scripts/common.sh:313`). The install runs that fix after projection parts and reboots; uninstall calls the restore (`HMG-Leafia-Plus/packages/wireless-carplay-aa/scripts/post.sh:43`, `HMG-Leafia-Plus/packages/wireless-carplay-aa/scripts/preun.sh:10`). NEMESIS's `adb.tcp` package instead snapshots live settings/files, writes `ro.adb.secure=0`, `persist.service.adb.tcp.enable=1`, `service.adb.tcp.port=5555` into `/system/build.prop`, removes the ADB-hide feature file, sets live properties, and restarts `adbd`; uninstall restores its snapshot (`hmg_nemesis/Sources/packages/adb-tcp/scripts/common.sh:260`, `hmg_nemesis/Sources/packages/adb-tcp/scripts/common.sh:288`, `hmg_nemesis/Sources/packages/adb-tcp/scripts/common.sh:307`). Its metadata calls this “TCP ADB”; HMG-API's notes identify NEMESIS “Enable ADB” with the conflicting stock switch (`hmg_nemesis/Sources/packages/adb-tcp/NEMESIS.data:3`, `HMG-API/CLAUDE.md:56`).

**Mod model.** `mod.json` declares identity, compatibility, parts with setting conditions, feature flags, hooks, and optional network requests; `settings.json` defines toggles and apply behavior (`HMG-API/mods/wireless-carplay-aa/mod.json:1`, `HMG-API/mods/adb/settings.json:1`). The app's switch calls `hmgapid enable/disable`, which creates/removes `.disabled`; file changes need Apply, while hooks can stop immediately (`HMG-API/core/app/java/hmgapi/app/ModsTab.java:167`, `HMG-API/core/hmgapid/hmgapid.c:457`). Install verifies the package and preserves settings/on-off state; the engine plans conflicts, supports owner overrides, journals applies, and restores stock (`HMG-API/core/runtime/java/hmgapi/engine/Packages.java:20`, `HMG-API/core/runtime/java/hmgapi/engine/Engine.java:20`, `HMG-API/docs/mod-reference.md:140`). Mod services have per-service logs; wireless declares log tags, while the common Logs tab reads the HMG-API log keeper (`HMG-API/docs/mod-reference.md:51`, `HMG-API/mods/wireless-carplay-aa/mod.json:57`, `HMG-API/core/app/java/hmgapi/app/LogsTab.java:9`).

## Historical design inferences and remaining car checks

A standalone NEMESIS package/root service could reproduce the **ADB coexistence fix** with full-root `setprop`, a saved baseline for both persistent properties, `adbd` restart, boot-time enforcement of the old switch at zero, and a reboot after changing it; it need not port HMG-API hooks, patch engine, or `hmgapid` merely to set these properties (`HMG-API/mods/adb/patches.json:3`, `HMG-Leafia-Plus/packages/wireless-carplay-aa/scripts/common.sh:313`). Our implemented `wireless-adb` module now has its own toggle/state, transactional restore, boot reconciliation, and conflict handling; see `.agents/wireless-adb.md`. The now-implemented **wireless projection** port was the larger task anticipated here: feature-file edits, stock-version checks, hooks/native patches and possibly persistent firewall rules on affected models (`HMG-API/mods/wireless-carplay-aa/mod.json:11`, `HMG-API/mods/wireless-carplay-aa/mod.json:68`, `HMG-API/docs/mod-reference.md:236`). Confirm the target unit's ADB socket and firewall, hotspot DHCP, and the effect of toggling/rebooting on-car before implementation.
